## Защита данных при выпуске

- Публичный portable собирается с пустым `data/`, без переноса локального
  профиля, истории чатов, ключей и `environment.env`.
- Установщик проверяется в отдельном каталоге; запуск использует отдельные
  `--user-data-dir`, `--extensions-dir` и `XYNAPSE_GLOBAL_DIR`.
- `scripts/verify-release-secrets.py` проверяет исходники и распакованные
  артефакты. Локальные ключи сравниваются только в памяти, включая UTF-8,
  UTF-16LE и Base64; в отчёт попадают только пути и категории совпадений.
- ZIP и VSIX проверяются после декомпрессии. Сжатый установщик дополнительно
  проверяется по установленным файлам.
- Portable использует нативные модули готовой Electron-сборки без замены
  копиями из среды разработки. Файлы установленной и portable-версии
  сверяются с исходной desktop-сборкой по SHA-256.
- Одно точное содержимое заведомо невалидного PEM-макета в SSL-тесте отмечено
  SHA-256 исключением. Изменённый макет и совпадение с настоящим локальным
  ключом по-прежнему останавливают проверку.
- Проверка сканера: обнаружение контрольного значения в трёх кодировках,
  безопасный шаблон и значение внутри VSIX — 5 проверок прошли.

Отчёты сканирования не содержат самих ключей. Такая проверка снижает риск
утечки, но не заявляется как доказательство отсутствия любого мыслимого
формата секрета.

## Границы утверждений

- Успех API-проверки означает совместимость проверенного запроса с моделью на
  дату теста; он не гарантирует постоянную доступность внешнего сервиса.
- Проект не заявляет, что исходный текстовый перечень из 1000 пунктов был 1000
  независимыми автоматизированными тестами. Для релиза учитываются только
  результаты реальных тестовых раннеров.
- Отдельное исследование Council/BVC измеряет наблюдавшиеся эффекты на
  исследованной выборке и не доказывает универсальное улучшение для любой
  задачи или модели.
- Windows-артефакты выпускаются без заявления о подписи Authenticode, если
  проверка подписи не подтвердит обратное.

## Воспроизведение

Команды запускаются из корня репозитория, если рядом не указана другая рабочая
директория.

```powershell
# Code OSS (Node 22.21.1)
Set-Location vscode
npm ci --legacy-peer-deps
npm run gulp compile-build-without-mangling
npm run compile-check-ts-native
npm run monaco-compile-check
npm run vscode-dts-compile-check
npm run valid-layers-check
npm run eslint
npm run hygiene
npm run test-node
npm run test-browser-no-install

# Сборочные скрипты
cd build
npm run typecheck
npm test
```

Команды Assistant выполняются с Node.js 20.19.0 в соответствующих пакетах:

```powershell
Set-Location plugins/continue-main/core
npm run vitest
npm test
npx tsc --noEmit
npm run lint
npm run build

Set-Location ../gui
npm test
npx tsc --noEmit
npm run lint
npm run build

Set-Location ../extensions/vscode
npm test
npx tsc --noEmit
npm run lint
npm run esbuild
```

Точные имена скриптов и итоговые команды в опубликованной версии сверяются с
`package.json`; этот раздел обновляется, если пакет использует другое имя.

## Проверка опубликованных файлов

### Встроенный Assistant с BVC 0.1.0

Windows x64 упаковщик читает закреплённый VSIX из
`vscode/build/xynapse-assistant.json`. Относительный путь разрешается от корня
репозитория; другой путь можно передать через `XYNAPSE_ASSISTANT_VSIX`.
SHA-256 всё равно должен совпадать с закреплённым значением. Отсутствующий или
изменённый пакет останавливает сборку; возврата к кэшу нет.

Содержимое `extension/` переносится без пересборки и изменения байтов в
`resources/app/extensions/xynapse-assistant`. Копия этого расширения из
`.build/extensions` исключается целиком. Общие фильтры исходных карт и
минификация JSON к переданному пакету не применяются. Проверяются все файлы,
а не только версия расширения 1.0.0, общая для старого и нового VSIX.
Перезапись Windows-метаданных нативных модулей также исключает этот каталог:
байты `.node`-файлов остаются такими же, как в переданном пакете.

Переданный пакет:
`artifacts/bvc-0.1.0-20260905/xynapse-assistant-bvc-0.1.0-win32-x64.vsix`.
Его SHA-256 — `e3f4698ca2a6459e29e94e11b5d132eac8c835ef903574cf88d8427a6e831360`.
Архив не хранится в Git; для воспроизведения требуется этот локальный файл
либо идентичный опубликованный артефакт. Отдельный `xynapse-bvc-0.1.0.tgz`
не заменяет расширение.

По handoff интеграции BVC от 5 сентября выполнены 103 теста: 43 теста ядра,
59 тестов провайдеров/политики/интеграции и 1 Jest-тест с 24 утверждениями.
Этот результат не обозначает новый прогон на платных моделях. В рамках
упаковки повторяются проверки типов и тесты сборщика, затем сверка полного
VSIX с установленной IDE и распакованным portable, включая путь реально
активированного расширения.

### Артефакты IDE

Имена файлов согласованы с GitHub updater в `vscode/product.json`:

- `XynapseSetup-x64-1.108.0.exe`
- `Xynapse-portable-win32-x64-1.108.0.zip`
- `xynapse-assistant-win32-x64-1.0.0.vsix`
- `SHA256SUMS.txt`

Версия standalone-расширения — 1.0.0; версия IDE — 1.108.0. Проверка подписи
должна показывать `NotSigned`: сертификат подписи кода не используется.
Хеш исходного коммита записывается сборщиком в `resources/app/product.json`.

Локальная готовность не означает публикацию. Публикация считается проверенной
только после повторного скачивания файлов с GitHub и совпадения SHA-256 с
`SHA256SUMS.txt`; факт наличия локальных файлов не подменяет эту проверку.
